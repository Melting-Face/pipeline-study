# 분석 리포트 (`docs/analyses/`)

레이크하우스 데이터로 **질문에 답한 결과**를 두는 곳이다. 규칙 정본은
[`../conventions/analysis.md`](../conventions/analysis.md) §5 리포트 규칙.

| | 내용 |
| --- | --- |
| 파일명 | `<NN>-<slug>.md` (`NN`=2자리, `slug`=영문 kebab-case) |
| 저자 | **`analyst`** — `tech-writer`는 표현만 손본다(이중 소유) |
| 독자 | 저장소를 **아는 사람**. 모르는 사람 대상 원고는 [`../posts/`](../posts/) |
| 구성 | 질문 → 데이터·코호트 → 방법 → 결과 → 해석 → **한계** |

- **결론에 쓰는 수치는 gold/dbt 모델을 경유**한다. 임시 SQL 결과를 옮기지 않는다.
- **수치에는 산출 엔진을 병기**한다 — 같은 SQL이 엔진에 따라 값이 갈린 사례가 있다.
- **한계 섹션을 비우지 않는다** — 확인하지 못한 것을 확인하지 못했다고 쓴다.
- 🔴 **소규모 셀(5 미만)은 마스킹**하고 개별 레코드를 남기지 않는다
  ([`../security.md`](../security.md)). 이 디렉터리의 `*.csv`·`*.parquet`는
  `.gitignore`와 `no-health-data-files` 훅이 막지만 **`.json`은 정규식 밖**이다.

⚠️ **아직 리포트가 없다.** 이 파일은 디렉터리를 실재시키는 자리표시자다 — git이 빈
디렉터리를 추적하지 않아, 이 README가 없으면 `docs/analyses/`를 가리키는 링크가
**작업 트리에서만 살아 있고 클론에서는 죽는다**(CI에서 실제로 그렇게 잡혔다).
