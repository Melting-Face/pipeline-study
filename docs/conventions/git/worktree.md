# 병렬 세션 — 세션별 git worktree

> **범위**: 여러 세션/에이전트가 **하나의 저장소를 동시에** 쓸 때의 규칙이다.
> 브랜치 전략·커밋 단위 등 **1인 작업 흐름의 정본은 [`../git.md`](../git.md)** 이며,
> 요약은 [`CLAUDE.md`](../../../CLAUDE.md) §병렬 세션에 있다.

## 원칙

- **쓰기 세션 하나 = worktree 하나 = 브랜치 하나 = PR 하나.** 각 세션은 자기 worktree에서만 쓴다.
- 한 브랜치는 **한 worktree에만** 체크아웃된다 → 같은 브랜치의 중복 작업이 자연스럽게 막힌다.
- **루트 워킹트리는 읽기·허브 전용**이다. worktree 생성·정리만 루트에서 한다.
- **충돌은 git이 처리한다.** 각 worktree에서 `origin/main` 기준으로 rebase하고, 같은 파일을
  두 세션이 고쳤다면 늦게 머지하는 쪽이 rebase한다. **세션 간 통보·리스·레지스트리 규약은 없다** —
  공유 트리 전제를 없애 그 규약들이 지키던 위험(인덱스 교차 오염·발밑 브랜치 전환)이 사라졌다.

## 왜 지켜지지 않는가 (실측)

규칙이 조건부(*"main 워킹트리에 다른 세션이 있으면 옮긴다"*)였을 때 **세션은 그냥 루트에서 시작**했고,
여러 세션이 한 워킹트리를 공유해 다음 증상이 났다.

| 증상 | 실제로 일어난 일 |
| --- | --- |
| **커밋 분리 불가** | 한 파일에 여러 미션의 변경이 섞여 「한 커밋 = 한 관심사」를 지킬 수 없었다 |
| **인덱스 경합** | 한 세션이 `git add` 해둔 것이 다른 세션의 커밋에 딸려갔다 |
| **브랜치 전환 불가** | 다른 세션이 같은 트리를 쓰는 중이라 `git switch`가 그들의 발밑을 흔들었다 |

**같은 규칙이 같은 방식으로 반복 실패했으면 규율이 아니라 설계 문제다** — 그래서 조건부 규칙을
의무로 바꾸고 기계로 집행한다. 공유 트리 시절의 사고 사례와 그때의 규율(pathspec 커밋·겹침 4축 등)은
전제가 사라져 저장소 밖 기록으로 옮겼다.

## 집행 — `scripts/worktree_guard.py`

| 막는 축 | 결정 | 비고 |
| --- | --- | --- |
| 루트 워킹트리의 파일 도구 쓰기(`Edit`·`Write`·`NotebookEdit`) | `deny` | 예외 1종: `.claude/settings.local.json`(링크 자산) |
| 루트 워킹트리의 `git commit`(`cd` 체인·`git -C <루트>` 포함) | `deny` | |
| 루트 워킹트리의 **Bash 쓰기** | **보지 않는다** | 선언된 공백 — 아래 참고 |

- **판정축**: `git rev-parse --absolute-git-dir` **==** `--git-common-dir`이면 메인 워킹트리다.
  `.git`이 디렉터리냐 파일이냐로 재지 않는다(submodule·`repair` 중간 상태에서 갈린다).
- **판정 대상은 이 저장소뿐이다** — 볼트처럼 다른 git 저장소의 메인 워킹트리는 통과한다.
- **Bash 쓰기를 보지 않는 이유**: 문자열 휴리스틱(리다이렉트·`sed -i` 탐지)은 `2>/dev/null` 같은
  **순수 조회까지 막는 오탐**을 냈고, 구멍을 닫을 때마다 다른 축이 열리는 fix 연쇄를 낳았다.
  봉쇄가 목표가 아니므로 커밋 축만 남겼다. 이 결정은 테스트 셀
  `test_bash_write_in_main_tree_is_not_guarded`가 고정한다 — 되살리려면 그 셀부터 바꿔야 한다.
- **커밋 판정의 한계**(문자열 판정이라 봉쇄가 아니다 — 커밋은 permissions `ask`가 한 겹 더 받친다):
  `cd` 추적은 리터럴 경로만 따라가고 `~`를 펴지 않는다. 변수·명령치환·중첩 셸(`bash -c`),
  `git -c k=v commit`, `--git-dir`/`--work-tree`, `GIT_DIR=` 접두, `-C`를 두 번 준 형태는 못 본다.
- **`ask`가 아니라 `deny`인 이유**: auto 모드 분류기가 파일 도구의 `ask`를 흡수한다.

## 이주와 배선 반영 시점

- **세션 도중 이주는 가능하다** — `worktree-new.sh`로 만들고 `EnterWorktree`의 `path`로 들어간다.
  순서를 바꾸면(`EnterWorktree`가 직접 생성) 비커밋 자산 링크가 없다.
- **hook 배선은 세션 시작 시점 스냅샷이다** — 이주해도 그 세션의 배선은 그대로다.

  | 축 | `EnterWorktree` 이주를 따라가나 |
  | --- | --- |
  | transcript 저장 디렉터리 | 따라감 |
  | hook 배선 | **안 따라감** |

  「안 막힘」의 원인 후보는 둘이다 — ⓐ 배선 미로드 ⓑ 배선은 로드됐으나 스크립트 경로가 없어
  exec 실패(무출력·비-0 = fail-open). 관측이 같으므로 `/hooks` 목록과 가드 **수동 호출**로 가른다.

## 도입 절차 — `scripts/worktree-new.sh`

```bash
./scripts/worktree-new.sh <type>/<kebab-요약> [--venv]
# 예: ./scripts/worktree-new.sh feat/spark-thrift-poc --venv
```

하는 일: 브랜치명 규약([`../git.md`](../git.md) §1) 검사 → **브랜치 상태 4축 판정** → `worktree add`
(시작점 `origin/main`, **추적 안 함** — push가 main을 향하지 않게) → **비커밋 자산 심볼릭 링크** →
(옵션) `uv sync` + `dbt deps`.

- **브랜치 상태 4축**: 신규는 `-b`로, 로컬에 이미 있으면 `-b` 없이, 원격에만 있으면 `origin/<B>`를
  시작점으로 명시하고, **다른 worktree가 점유 중이면 그 디렉터리를 알려주고 멈춘다**(설계다 — 점유가
  중복 작업의 lock이므로 우회하지 않는다).
- **링크 자산은 2종**이다 — `.env`(비밀정보 사본을 늘리지 않는다)·`.claude/settings.local.json`
  (권한이 갈라지면 worktree마다 프롬프트가 달라진다). `settings.json`·`agents/`는 커밋 대상이라
  자동으로 따라온다. ⚠️ 링크를 **통해 쓴 내용**은 원본에 반영된다.

### `.venv`는 링크하면 **반쪽 격리**가 된다

venv의 editable 설치가 **메인 트리의 소스**를 가리켜, 링크하면 SQL·문서는 격리되는데 **파이썬 코드는
메인 트리 것이 돈다**. 그래서 링크하지 않고 `uv sync` 한다(`--venv`). 비용이 있으므로 문서·SQL만
만지는 작업이면 생략한다(기본값이 생략).

### worktree venv는 **Python 마이너 버전이 갈릴 수 있다**

`requires-python` 범위 안에서 `uv sync`가 그때 가용한 최신을 잡으므로 같은 lock인데도 메인 트리와
마이너 버전이 갈릴 수 있다. 버전을 맞춰야 하는 검증이면 `uv sync --python 3.12`처럼 **명시**한다.

### `.gitignore`의 **끝 슬래시**가 링크를 놓친다

`foo/`처럼 **슬래시로 끝나는 패턴은 디렉터리만** 매칭한다. worktree에서 링크 자산은 **파일 취급**이라
무시되지 않고 `??`로 잡혀 `git worktree remove`가 거부한다. 링크 대상 경로의 패턴에는 끝 슬래시를
붙이지 않는다.

## 정리

```bash
git -C <루트> worktree remove [--force] <worktree 경로>   # --force는 링크만 끊고 링크 원본은 지우지 않는다
git -C <루트> worktree prune
git -C <루트> branch -D <브랜치>                          # PR 머지 후
```

squash 머지 저장소라 `git branch -d`·`--is-ancestor`는 머지된 브랜치를 미머지로 판정한다 —
머지 여부는 `gh pr list --head <브랜치> --state merged`로 본다.
