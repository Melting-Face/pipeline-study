# 외부 공개 컨벤션 (publishing)

> **정본.** 저장소 산출물을 **저장소 밖 사람에게 보이는 형태**로 만들 때의 규칙이다.
> 블로그 글(티스토리 등)·공유용 정리 자료·발표 자료가 대상이며, 작성 주체는
> [`tech-writer`](../../.claude/agents/tech-writer.md) 워커, 근거 수집은
> [`researcher`](../../.claude/agents/researcher.md)다.
> 거버넌스 정본은 [`security.md`](../security.md), 분석 수치 규칙은 [`analysis.md`](analysis.md).

## 0. 왜 별도 문서인가 — 공개는 커밋보다 강한 기준이다

[`security.md`](../security.md)와 [`general.md`](general.md#비밀정보-secrets)의 금지선은
**"저장소에 커밋하지 않는다"** 기준이다. 그런데 이 저장소에는 커밋해도 되지만 **공개하면 안 되는 것**이 있다.

| 축 | 저장소 커밋 | 외부 공개 |
| --- | --- | --- |
| 컬럼명·스키마 구조 | ✅ ([`dataset_schema.md`](../dataset_schema.md)) | ⚠️ 범위 내에서만, 값 제외 |
| 집계 수치(코호트 크기 등) | ✅ ([`analyses/`](../analyses/)) | ⚠️ **소규모 셀(<5) 마스킹** 후 |
| 내부 경로·클러스터/버킷 이름 | ✅ | ❌ 플레이스홀더로 |
| 원천 데이터 행 값 | ❌ | ❌ (DUA **재배포 제한**) |
| 자격증명·엔드포인트 | ❌ | ❌ |

**되돌릴 수 없다.** 공개된 글은 캐시·인덱싱·재게시로 남는다.
그래서 공개 경로에는 **되돌림이 아니라 사전 차단**을 건다.

**그런데 이 저장소는 공개다 — `git push`가 곧 발행이다**(2026-08-20 `security` 컨펌에서 지적).
위 표의 "커밋 / 공개" 대비를 **"커밋은 안전지대"로 읽으면 틀린다.** 둘의 실제 차이는 노출 여부가
아니라 **독자와 증폭**이다:

| | 저장소 커밋 | 블로그·공유물 |
| --- | --- | --- |
| 독자 | 찾아온 사람 — **맥락을 가지고 읽는다** | 검색으로 온 사람 — **맥락 없이 조각만 읽는다** |
| 증폭 | 낮음 | 검색 인덱싱·재게시·스크랩 |
| 정정 | 커밋으로 정정 가능(히스토리는 남음) | **사실상 불가** |

→ 그래서 **초안도 컨펌 전에는 커밋하지 않는다**(§5). "draft니까 괜찮다"가 성립하지 않는다.

## 1. 절대 나가면 안 되는 것

1. **원천 데이터의 행 단위 값**·식별자·준식별자 조합
   (예: 의료 데이터셋의 입퇴원 시각 + 생년 + 병동)
   → **DUA·재배포 제한이 걸린 데이터셋**이면 값의 공개는 계약 위반 소지다. 현재 적재분인
   MIMIC-IV·eICU가 그 경우다 — **PhysioNet Credentialed License + DUA**([`security.md` §0](../security.md)).
2. **소규모 셀 — 관례상 5 미만.** 집계여도 셀이 작으면 재식별 경로다
   ([`security.md` §2-3](../security.md)). 마스킹(`<5`)하거나 구간으로 묶는다.
3. **외부 데이터 결합 결과** — 재식별 금지(개인정보보호법 **제28조의5**)와 **DUA 재배포 제한**에 걸린다.
   근거 조항은 [`security.md` §1-2](../security.md) 매핑 표에서 확인한다 —
   🔴 **표에 없는 조항을 근거로 적지 않는다.**
4. 자격증명·토큰·엔드포인트·호스트명·내부 IP·`.env` 값·클러스터/버킷/DB 이름.
5. **실행 로그·에러 스택·스크린샷** 안의 위 항목.
   **가장 자주 새는 경로다** — 붙여넣은 로그는 한 줄씩 본다.
6. **노트북 셀 출력.** `nbstripout` 훅이 `.ipynb`를 막지만, **본문에 옮겨 적으면 훅을 우회한다.**

### 대체 방법

- 실데이터 예시가 필요하면 **합성 예시**를 만들고 *"예시는 합성 데이터"* 를 **본문에 명시**한다.
- 접속 문자열·경로는 `<HOST>`·`<BUCKET>`·`<PROJECT_DIR>` 플레이스홀더로.
- 규모감이 필요하면 값 대신 **자릿수·구간**으로("수십만 행 규모").

## 2. 수치 규칙

- **결론 수치는 gold/dbt 모델을 경유**한다. 임시 SQL 결과를 글에 옮기지 않는다([`analysis.md`](analysis.md)).
- **산출 엔진을 병기**한다 — 같은 SQL이 엔진에 따라 갈린 실사례가 있다(`dbt.datediff`:
  Spark는 경과시간 `ceil`, Trino는 경계 교차). *"(Trino 기준)"* 처럼 적는다.
- 저장소 산출물에 없는 수치는 **쓰지 않는다.** 필요하면 `data-verifier` 대조를 거친다.
- 벤치마크·성능 수치는 **측정 조건**(하드웨어·데이터 크기·반복 횟수)을 함께 쓴다. 없으면 뺀다.

## 3. 출처·인용 규칙

- 외부 주장은 **제목 · 링크 · 버전/날짜**를 남긴다(전역 규약 *authentic source with reference title*).
- 출처 등급은 `researcher`가 판정한다(**A 1차 / B 준1차 / C 2차 / D 미상**).
  **C·D만으로 단정하지 않는다** — C가 인용한 A를 찾아가 확인한다.
- 저장소 **내부 경로를 그대로 노출하지 않는다**(링크가 깨지고 내부 구조를 흘린다).
- 타인의 코드·문서를 인용하면 **라이선스·저작자**를 표기한다.

## 4. 산출물 규약

- 경로: **`docs/posts/<NN>-<slug>.md`** (`NN`=2자리 일련번호, `slug`=영문 kebab-case)
  — `docs/analyses/<NN>-<slug>.md`(내부 결론)와 **대칭**이며, 소유 워커가 다르다.
- 첨부: `docs/posts/assets/<NN>-<slug>/`
  - **이미지만.** `*.csv`·`*.parquet`·`*.ipynb`·덤프 첨부는 **DUA 재배포**에 해당한다 — 금지.
  - **그림도 소규모 셀(<5) 마스킹 대상**이다. 히스토그램 꼬리 bin·산점도 개별 점·희소 히트맵 셀은
    표와 **같은 규칙**을 받는다(표만 가리고 그림을 놓치는 실수가 가장 흔하다).
- 프론트매터:

```yaml
---
title: <공개 제목>
status: draft | security-reviewed | published
target: tistory | github | slide | other
source_of_truth: <근거가 된 저장소 문서·모델 경로>
engine: <수치가 있으면 산출 엔진>
security_review: <미실시 | YYYY-MM-DD 승인 | 지적사항 N건>
---
```

## 4-1. 위키 산출물 규약 (`wiki/`)

**GitHub 위키는 새 축이 아니라 새 매체다.** 독자는 `docs/posts/**`와 같은
**저장소를 모르는 사람**이고, 소유 워커도 `tech-writer`로 같다. §1~§3의 반출 통제와
수치 규칙이 **그대로 적용**된다. 다른 것은 산출물 형태와 게이트 위치뿐이다.

- 경로: **`wiki/<slug>.md`** — **평평하게** 둔다. 위키는 계층 사이드바가 없어
  하위 디렉터리를 만들면 탐색이 오히려 나빠진다.
- 파일명은 **영문 kebab-case**(URL에 그대로 노출), 제목(H1)은 한국어.
  `docs/posts/`의 `NN-` 일련번호는 **붙이지 않는다** — 위키는 시간순 발행물이 아니라
  갱신되는 페이지 모음이라 번호가 낡는다.
- 고정 이름 둘: **`Home.md`**(랜딩) · **`_Sidebar.md`**(사이드바).
- **`wiki/README.md`를 두지 않는다** — 미러되면 `README`라는 엉뚱한 페이지가 생긴다.
- **프론트매터를 쓰지 않는다** — 위키는 YAML 프론트매터를 렌더링하지 못하고
  본문 맨 위에 그대로 노출한다. `status`·`security_review` 추적은 커밋 이력이 대신한다.
- 첨부 이미지는 §4와 같은 규칙(소규모 셀 <5 마스킹 포함).

### 링크 표기

저장소 원본에는 **`.md`를 붙여** 쓰고, 미러 단계에서
[`scripts/wiki_linkify.py`](../../scripts/wiki_linkify.py)가 접미어를 뗀다.

```text
저장소 원본:  [텍스트](other-page.md)     ← 실파일이라 doc_lint --links가 검사한다
미러 결과  :  [텍스트](other-page)        ← 확장자가 붙으면 위키에서 404다
```

예시를 펜스 블록에 둔 이유가 있다. `doc_lint --links`는 **인라인 코드 스팬을 건너뛰지 않아**
백틱으로 감싼 예시 링크도 실제 링크로 보고 `dead-link`을 낸다(2026-08-27 실측).
문서에 링크 예시를 적을 때는 **펜스 블록**을 쓴다.

🔴 **원본에서 확장자를 생략하지 않는다.** 그렇게 하면 링크 검사기가 대상을 못 찾아
**검사가 통째로 죽는다** — 편해지는 쪽이 아니라 통제를 유지하는 쪽을 고른 것이다.
같은 이유로 **참조형 링크(`[x]: url`)와 HTML `<a href>`는 쓰지 않는다**(변환 대상 밖).

### 게이트는 커밋 시점으로 앞당긴다

위키는 `main` push 시 GitHub Actions가 **자동 미러**하므로 §5의 "사람이 업로드" 단계가
없다. 그렇다고 게이트가 사라지는 것이 아니라 **한 칸 앞으로 옮겨간다**.

```
tech-writer 초안(wiki/**)  →  security 컨펌  →  사용자 확인  →  커밋·푸시  →  기계가 미러
                                            ↑ 여기가 발행 게이트다
```

🔴 **`wiki/**` 커밋 전에 `security` 컨펌을 받는다.** 저장소가 공개라 커밋이 곧 공개인데,
위키는 거기서 **회수 지점이 하나 더 늘어난다**(저장소 이력 + 위키 저장소 이력).
미러를 자동화한 것은 *배달*이지 *승인*이 아니다.

## 5. 공개 절차 (게이트)

```
tech-writer 초안(docs/posts/**, status: draft)   ← 아직 커밋하지 않는다
      ↓
security 컨펌  ← 필수. 지적 있으면 초안으로 되돌린다
      ↓  (status: security-reviewed)
사용자 최종 확인
      ↓
커밋·푸시(사람 승인) + 🧍 사람이 업로드   ← 워커는 여기 관여하지 않는다
      ↓
사람이 status: published 로 변경
```

- **`security` 컨펌 전에는 `docs/posts/**` 를 커밋하지 않는다.** 이 저장소는 공개라
  푸시가 곧 발행이고, 그러면 게이트가 **실제 공개 시점보다 뒤에** 서게 된다(§0).
  `git commit`·`git push`는 `permissions.ask` 대상이며, `tech-writer` 지시문도 이를 금지한다.

- 🔴 **발행(업로드)은 어느 워커도 하지 않는다.** 외부 발신은 **비가역**이라
  [`agents.md`](agents.md)의 비가역 목록과 같은 취급이다. `curl -X POST`·플랫폼 API·`gh` 발행 금지.
- `status: published`는 **사람이** 붙인다.
- **`security` 컨펌은 "훑어봤다"로 끝내지 않는다.** 무엇을 **어떤 명령·절차로** 확인했는지 남긴다
  ([philosophy.md](../philosophy.md) 원칙 7 — 부정 결과는 관측 경로가 살아 있었음을 함께 확인해야 유효하다).

## 6. 정직성 — 원칙 7의 공개판

- 🔴 **"고쳤다"를 "확인했다"로 쓰지 않는다.** 저장소에 `미확인`·`미측정`으로 남은 것은
  공개 글에서도 **그대로 미확인**이다.
- **실패·번복 이력을 지우지 않는다.** 이 저장소에서 값이 큰 문서는 대부분 "이렇게 틀렸었다"를 담고 있다.
- 기계 강제가 없는 규칙을 **"막혀 있다"로 쓰지 않는다**(§7 참조).

## 7. 강제 수단과 그 한계 (정직하게)

| 층 | 수단 | 실효 |
| --- | --- | --- |
| 경로 경계 | `worker_path_guard.py` — `allow: docs/` · `README.md` | 쓰기 경로 이탈을 즉시 `deny` |
| **판정 근거 문서 차단** | 같은 가드의 **`except` 축** | 판정 대상이 자기 판정 근거를 못 고치게 한다. **문안 정합도 예외가 아니다** |
| 읽기 전용(researcher) | `disallowedTools: Write, Edit, NotebookEdit` | ✅ **실발동 확인** — `No such tool available: Write … disabled for this session`. `Bash` 경유는 미차단 |
| 외부 접촉 | ~~`permissions.ask`의 `WebFetch`·`WebSearch`~~ | **죽은 규칙(실측)** — `WebSearch` 3회·`WebFetch` 6회 **전부 프롬프트 없이 통과**(허용목록 밖 도메인 포함). 맨이름은 `ask`에서 매칭되지 않는다. **질의 유출의 사람 관측점은 없다** |
| 발신(egress) 차단 | `permissions.deny`의 `curl`/`wget` **발신 동사** | 🟡 **동사만 본다.** 못 막는 것: `python`/`node` 경유(`urlopen(data=…)` 실측 통과) · GET+쿼리스트링+명령치환 · 변수 조립(`-X${M}`) · `scp`/`ssh`/`nc` |
| 발행 금지 | 지시문 + `permissions.ask`(`gh api`·`gh pr/issue/gist/release`) | 🟡 **규율 중심** |
| **커밋 = 공개** | `permissions.ask`의 `git commit`·`git push` + §5 컨펌 전 커밋 금지 | 🟡 저장소가 공개라 **푸시가 곧 발행**이다(§0) |
| 매체 도메인 | `permissions.deny`의 `Bash(*tistory.com*)` | **방어선이 아니다** — `Bash` 한정이라 `WebFetch`에 무효이고 매체는 무한하다(velog·medium·brunch…). **실수 방지 표식**으로만 둔다 |
| 셀 출력 | `nbstripout` 훅 | ✅ 기계 강제(단 **본문 전사는 우회**) |

**✅는 "그 도구 경로에서만" 참이다.** 경로 경계·읽기 전용은 실측으로 작동을 확인했지만
**셋 다 `Bash`를 못 막는다.** 발신·질의 축은 아예 통제가 없다.
즉 이 문서의 실효는 여전히 **사람의 최종 확인**에 걸려 있고, 그래서 §5의 마지막 게이트를
사람이 갖는다 — **자동화하지 않는 것이 설계다.**

**패턴 방어의 한계를 정직하게 적는다.** `deny`는 문자열 매칭이라 **적대적 우회를 막지 못한다**
(실측: `curl -X POST`는 막았는데 `curl -sS -X POST`가 통과 → 교정, 그래도 `curl --json`·
`python3 urlopen(data=…)`은 통과했다). 이건 **실수 방지**이지 봉쇄가 아니다.
그러므로 **`researcher`가 인젝션을 따르지 않는 것**과 **사람이 발행 직전에 읽는 것**이 실제 방어선이다.
