# 오브젝트 스토리지 (아키텍처 · 프로젝트 관점)

이 문서는 **「무엇이 S3 슬롯을 차지하고, 갈아끼운다면 무엇으로 판정하는가」** 를 갖는다.
현행 선택의 근거, 교체 검토를 연 **단일 동기**, 후보 비교와 **판정 수단**,
재검토 트리거가 여기 있다.

반대로 **정본이 아닌 것**을 먼저 밝힌다 — 체크섬 결함의 증상·SDK 버전 경계·적용 대상
전수·오진 갈래는 [../conventions/k8s/checksum.md](../conventions/k8s/checksum.md)가,
path-style·카탈로그 정합 규칙은 [../conventions/k8s.md](../conventions/k8s.md) §11이,
자원 수치는 [../resource-sizing.md](../resource-sizing.md)가,
프로브의 구현 세부·인자·종료 코드는
[`scripts/storage_conformance_probe.py`](../../scripts/storage_conformance_probe.py)의
머리 주석이 갖는다. **여기에 복제하지 않는다** — 복제하면 양쪽이 각자 낡는다.

**실행 규약의 정본은 [../test/manual-gates.md](../test/manual-gates.md) §5-5다** — 언제 통과시키는가,
종료 코드의 의미, 대조군 규율, 전제, 첫 실행 범위, 미검사 축이 거기 있다. 이 문서는 *왜 이 스위트가
유일한 판정 수단인가*와 후보 평가를 갖고, 인자·구현 세부는 스크립트 주석이 갖는다.

## 개요

오브젝트 스토어는 파일시스템이 아니라 **키 → 바이트열 + 메타데이터**의 평평한 저장소다.
디렉터리도 부분 수정도 없고, 쓰기는 객체 단위 교체이며 나열은 프리픽스 질의다.
이 모델 위에 **S3 API**가 사실상의 공통 계약으로 얹혀, 스토어를 갈아끼워도
클라이언트를 안 바꾸는 이식성이 생긴다.

**그 이식성은 계약의 *범위*까지만이다.** S3는 단일 명세가 아니라 연산·헤더·프레이밍의
집합이고, 호환 스토어마다 구현한 부분집합이 다르다. 그래서 이 축의 실패는
"안 붙는다"가 아니라 **"붙는데 일부가 다르게 동작한다"** 로 온다.

이 저장소에서 그 슬롯이 담는 것은 셋이다.

| 담는 것 | 경로·용도 |
| --- | --- |
| Iceberg 데이터·메타데이터 파일 | `s3://warehouse` — 레이크하우스 본체 |
| Flink 체크포인트 | 스트림 상태의 내구 저장 |
| 카탈로그 Postgres 백업·WAL 아카이브 | CNPG Barman Cloud 플러그인의 대상 |

⇒ **레이크하우스의 바닥**이다. 여기서 조용히 깨지면 위층 전부가 그 값을 신뢰한 채 돈다.

## 이 프로젝트에서의 위치 — ✅ 채택 (SeaweedFS)

현행은 **SeaweedFS**이고 K8s에 `StatefulSet` + PVC로 선다. 스토리지 **정본은 K8s 쪽**이고,
compose 정의는 남아 있되 `legacy-storage` profile로 **상시 기동만 끊겨** 있다.

**「중단」과 「삭제」는 다른 축이다** — 자원은 즉시 회수하되 정의를 남겨 롤백 비용을 0으로
둔다. 이 처리를 `trino`와 공유하지만 **사유는 다르다**: `trino`는 제거 대상의 유예이고,
`seaweedfs`는 **같은 기술의 정본이 다른 환경으로 옮겨간 것**이다.
compose 쪽을 보고 「미채택으로 내려갔다」로 읽지 않는다.

**오퍼레이터는 미채택 🔎다.** SeaweedFS 오퍼레이터는 master/volume/filer 분리로 상주가
순증하는데 이미 PVC라 막을 유실 급소가 없다 — 판정과 수치는
[../redesign.md](../redesign.md)와 [../resource-sizing.md](../resource-sizing.md)가 갖는다.

### 상태 마커 근거 — ✅는 슬롯을 말하고 교체 판정을 말하지 않는다

세 축을 뭉치면 이 문서가 거짓이 된다.

| 축 | 상태 | 근거 |
| --- | --- | --- |
| 슬롯 자체 | **✅ 채택** | 실데이터가 들어 있고 Spark·Flink·Dagster·dbt가 전부 여기를 본다 |
| 현행 구현 SeaweedFS | **✅ 채택 · 조건부** | 우회 설정을 전역에 깔아야 정상 동작한다. 아래 §동기 |
| 교체 후보 | **미판정** | 판정 수단이 실측뿐인데 후보에 겨눈 적이 없다 |

⇒ **✅를 「이 축은 닫혔다」로 읽지 않는다.** 미채택 🔎도 이행중 🚧도 아니다 —
🚧는 이행이 진행 중일 때의 표식이고, 옮기기로 한 대상조차 정해지지 않았다.

### 교체 검토의 동기 — 하나다

성능도 용량도 비용도 아니다. **정확성 축 하나**다.

**SeaweedFS는 AWS SDK의 flexible checksum을 풀지 못한다.** SDK가 본문을 `aws-chunked`로
감싸고 트레일러에 체크섬을 붙이는데, 스토어가 그 프레이밍을 벗기지 않아
**프레이밍 바이트가 객체 내용에 그대로 저장**된다.

이 결함의 모양이 교체 동기를 정한다.

- **쓰기는 성공 응답을 받는다.** 깨진 사실은 그 객체를 처음 읽는 **다른 프로세스**에서 난다.
- **그래서 저장소가 우회를 전역에 깔았다** — `AWS_REQUEST_CHECKSUM_CALCULATION`과
  짝 변수를 `when_required`로 못 박아 compose·`.env`·Dagster 상수·K8s 매니페스트 다수에
  넣었다. 적용 대상 전수는 [../conventions/k8s/checksum.md](../conventions/k8s/checksum.md) §4다.
- **한 곳만 빠져도 그 경로에서 조용히 샌다.** driver에만 주고 executor에 안 주면
  새는 식이고, 증상은 기동 실패가 아니라 **쓴 객체의 손상**이다.
- **"고쳤다"로 닫히지 않는다.** SDK를 올리면 기본값이 되살아나고, SDK v2를 쓰는 경로가
  새로 열릴 때마다 같은 축을 다시 봐야 한다.

⇒ **교체의 실질 목표는 「이 우회 설정을 걷어내는 것」** 이다. 성능 개선이 아니다.
목표를 이렇게 적어야 성공 판정이 흐려지지 않는다.

### 후보 평가 — 1차 조사 결과

등급은 **A 1차 / B 준1차 / C 2차 / D 미상**이다.

| 후보 | 판정 | 근거 | 등급 |
| --- | --- | --- | --- |
| **MinIO** | **탈락** | 저장소가 아카이브되어 읽기 전용이다. 아래 3축 분리 | A |
| **RustFS** | **후보** | 정식 릴리스 도달 · Apache 2.0 · 소스 저장소 안에 공식 Helm 차트 | A |
| **Ceph RGW** | **보류** | S3 호환은 가장 두터우나 상주 자원이 급소를 직격하고, 배치 전제가 안 선다 | A |
| **Garage** | **후보(약)** | 경량이나 공식 문서가 버저닝·object lock·SSE를 **미지원으로 명시**한다 | A |

**RustFS의 S3 서술 범위** — 멀티파트, `ListObjectsV2` 페이지네이션, 버저닝, object lock을
포함한다. 이 넷은 이 저장소가 실제로 쓰는 축이라 후보 자격의 최소선이다.

**Ceph RGW 보류 사유는 둘이고 성질이 다르다.**

| 사유 | 성질 | 풀리는 조건 |
| --- | --- | --- |
| 상주 자원이 **CPU 축**을 직격 | 예산 | 예산 분모가 CPU 축에서 올라갈 때 |
| OSD가 요구하는 raw block device가 없다 | 환경 | kind를 벗어날 때 |

⇒ **기각이 아니라 보류다.** 둘 다 후보의 결함이 아니라 **이쪽 환경의 제약**이라,
환경이 바뀌면 판정이 바뀐다. 기각으로 적으면 그 사실이 사라진다.

#### 🔴 MinIO 판정을 한 낱말로 뭉치지 않는다

*'지원 종료'* 한 낱말로 적으면 **서로 다른 세 축이 같은 무게로 섞인다.**
등급이 다른 사실을 한 칸에 담으면 A의 확실성이 C까지 번진다.

| 축 | 내용 | 등급 | 탈락에 기여하는가 |
| --- | --- | --- | --- |
| **아카이브** | 저장소가 읽기 전용이고 README 최상단이 유지보수 중단을 선언한다 | **A** · 1차 직접 관측 | **이것이 탈락 사유다** |
| **콘솔 기능 제거** | 관리 콘솔 기능이 축소됐다는 보도 | **C** · 2차 | 단독으로는 근거가 아니다 |
| **라이선스** | AGPLv3 | **A** | 아니다 — **현행 상태이지 최근 변경이 아니다** |

⚠️ **라이선스 축을 탈락 사유 목록에 올리지 않는다.** AGPLv3는 이 후보가 원래 그랬던
성질이고, 그것이 문제였다면 후보에 오르지도 않았다. 변화가 아닌 것을 변화로 적으면
다음 사람이 「최근에 바뀌었다」로 읽는다.

### 🔴 문서로는 후보를 가릴 수 없다 — 침묵이 조사의 결론이다

후보 3종의 **공식 문서 전문에서 체크섬 트레일러 관련 어휘가 0회 매칭**이다.
모집단은 각 해당 페이지 전문이다.

**0건을 「지원하지 않는다」로도 「지원한다」로도 읽지 않는다.** 이것은 부재의 증거가
아니라 **관측 경로가 그 축을 안 다룬다**는 뜻이다. 근거는 이 저장소 자신에 있다 —
**SeaweedFS도 어디에도 안 적혀 있었고 실측으로 드러났다.** S3 호환 스토어가
*"트레일러 체크섬을 푼다"* 를 문서에 적는 일이 드물다는 것이 이 침묵의 정체다.

⇒ **판정 수단은 실측 프로브 스위트 하나뿐이다.**

#### 프로브가 보는 축 5종

정본은 [`scripts/storage_conformance_probe.py`](../../scripts/storage_conformance_probe.py)다.
같은 스크립트를 대조군과 후보에 **같은 인자로** 겨눠 결과를 나란히 놓는다.

| 축 | 무엇을 보나 |
| --- | --- |
| P1 | SDK 기본 체크섬 PUT → 바이트 무결성. **이 축이 교체 동기 자체다** |
| P2 | 기본 설정 PUT/GET 왕복 — 단일 + 멀티파트 |
| P3 | Iceberg 테이블 write→read + FileIO 대용량 멀티파트 |
| P4 | warehouse 직접 나열 — FS 재귀 나열 ↔ `ListObjectsV2` 대조 |
| P5 | path-style · `ListObjectsV2` 페이지네이션 · 멀티파트 abort |

#### 🔴 대조군이 빨간 것을 먼저 확인하고 나서야 후보의 초록을 믿는다

**현행 SeaweedFS는 P1에서 반드시 실패해야 한다.** 실패하지 않으면 SeaweedFS가 고쳐진
것이 아니라 **프로브가 고장난 것**이다.

이유는 우회 설정이 전역에 깔려 있다는 사실 자체다 — 프로브가 그 설정을 **명시적으로
덮어쓰지 않으면** SDK 기본 경로를 안 타고 **조용히 초록**이 난다. 그 초록은
"통과했다"가 아니라 **"그 축을 안 쟀다"** 이고, 둘은 화면에서 같은 모양이다.

그래서 규율이 셋이다.

1. **덮어쓰기를 클라이언트 설정으로 명시**하고, 같은 실행에서 `when_required` 대조
   케이스를 함께 돌려 **둘이 갈리는지**를 본다.
2. **덮어쓰기가 먹혔는가는 결과가 아니라 전선에서 확인한다.** 겨냥한 프레이밍이
   실제로 요청에 붙지 않았으면 결과는 PASS가 아니라 **`미측정`** 이다.
3. **종료 코드는 「통과/실패」가 아니라 「관측 경로가 살아 있었는가」** 를 뜻한다.
   스토어가 응답한 오류는 **FAIL**이고 정보다. 접속 실패·모듈 부재는 **미측정**이고
   정보가 아니다. 둘을 한 코드로 뭉치면 못 돈 것이 실패로 위장한다.

#### 🔴 후보가 전부 초록이어도 판정은 부분이다

스위트가 **일부러 안 보는 축**이 넷이다. 빠뜨린 것과 구분하려고 적는다.

| 미검사 축 | 왜 남는가 |
| --- | --- |
| Java · AWS SDK v2 경로 | 스위트는 파이썬만 본다. 그런데 **손상은 Java에서도 났다** |
| Hadoop `s3a://` 클라이언트 | P4가 재는 나열은 구현이 다르다. 유지보수 프로시저의 근거로 못 쓴다 |
| barman-cloud WAL 아카이빙 왕복 | 오퍼레이터와 플러그인이 필요해 범위 밖이다 |
| 성능 · 내구성 · 동시성 | 이 스위트는 **정합성만** 본다 |

⚠️ 첫 행이 급소다 — 교체 동기인 체크섬 결함이 **Java 경로에서도 실재**하는데
판정은 파이썬 축에서만 나온다. **초록 5개를 전 경로 통과로 읽지 않는다.**

## 운영 메모

- **스토어를 바꾸는 판단에 성능 수치를 쓰지 않는다** — 이 축의 결정 근거는 정합성이다.
  측정 조건 없는 성능 비교는 결론을 흐린다.
- **우회 설정은 걷어내기 전까지 전 경로에 유지한다.** 한 곳만 빠지면 그 경로가 조용히
  샌다. 전수와 주입 형태는 [../conventions/k8s/checksum.md](../conventions/k8s/checksum.md) §4다.
- **체크섬으로 오진하기 쉽다** — 우회 설정을 넣었는데 증상이 안 바뀌면 **가설을 버린다.**
  넣은 채로 다른 원인을 찾으면 해소된 뒤에 잘못된 인과가 남는다. 갈래표는 같은 문서 §5다.
- **path-style 강제는 스토어가 바뀌어도 따라온다** — 규칙 정본은
  [../conventions/k8s.md](../conventions/k8s.md) §11이고, 교체 후보 검증에도 이 축이 P5에 있다.

### 재검토 트리거 — 시점이 아니라 조건

- **체크섬 우회 설정을 걷어내야 할 때** — 그것이 교체의 실질 목표다.
  이 트리거가 나머지 넷의 기준점이다.
- **호환성 결함이 체크섬 말고 세 번째 축에서 또 나올 때** — Rule of Three.
  두 번째까지는 개별 대응으로 막고, 셋째에서 **구현 선택 자체**를 다시 연다.
- **예산 분모가 CPU 축에서 상향될 때** — Ceph RGW 보류 사유의 절반이 그때 풀린다.
  ⚠️ **메모리 상향은 해당 없다.** 급소는 CPU 축이고 두 축을 바꿔 읽으면
  풀리지 않은 제약을 풀린 것으로 본다.
- **kind를 벗어날 때** — raw block device 제약이 소멸해 Ceph RGW 보류의 나머지가 풀린다.
- **오브젝트 총량이 재복사 불가 규모가 되기 전** — 이 트리거만 방향이 반대다.
  미루면 이전 비용만 커지므로, 다른 넷이 안 걸려도 이 선에서 한 번 판단한다.
