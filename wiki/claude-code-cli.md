# Claude Code CLI — 세션을 어떻게 띄우고 어떻게 끊는가

> 학습 노트. Claude Code를 이 프로젝트의 작업 도구로 쓰며 정리한 **CLI 실행 표면**과
> **세션 조작 표면**. 결론부터 쓰면 — **비용은 요청 수 × 컨텍스트 크기이므로,
> 「어떻게 띄우는가」보다 「어떻게 끊는가」가 중요하다.**
>
> 확인 기준: `claude --version` = `2.1.236` · 확인 시점 2026-09-09 (KST).
> 플래그·커맨드는 판올림마다 바뀐다. 아래 표는 **이 버전에서 확인된 것**이고
> 정본은 공식 문서다 — 표가 낡았을 때 독자가 스스로 판별할 수 있게 기준을 박아 둔다.

## 왜 CLI 표면을 따로 적는가

이 저장소의 다른 노트들은 파이프라인이 **에러 없이 깨지는** 이야기다.
이 노트는 좀 다르다 — **아무것도 깨지지 않았는데 내가 잘못 읽은** 이야기다.
대상도 파이프라인이 아니라 **그것을 만드는 도구** 쪽이다.

에이전트 CLI는 특이한 성질이 하나 있다 — **잘못 쓰면 느려지는 게 아니라 비싸진다.**
느려지면 알아채지만, 비싸지는 것은 청구서가 올 때까지 아무 증상이 없다.
그리고 그 비용이 어느 축에서 나가는지는 **기본 화면에 안 보인다.**

## 기동 — 실행 표면

플래그는 많지만 손에 붙는 것은 몇 개다. 아래는 **세션과 비용에 직접 닿는 것만** 골랐다.
전체 목록은 공식 CLI Reference가 정본이고, `claude --help`는 전부를 나열하지 않는다.

**세션을 어떻게 여는가**

| 형태 | 무엇이 달라지나 |
| --- | --- |
| `claude` | 대화식 세션 시작 |
| `claude "질문"` | 초기 질문과 함께 시작 |
| `claude -p "질문"` (`--print`) | 응답을 출력하고 **즉시 종료** — 스크립트·파이프용 |
| `claude -c` (`--continue`) | 현재 디렉터리의 **가장 최근** 세션을 이어붙인다 |
| `claude -r "<ID 또는 이름>"` (`--resume`) | **특정** 세션을 골라 이어붙인다(인자 없으면 피커) |
| `--fork-session` | 재개할 때 **새 세션 ID**를 만든다 — 원본을 안 건드리고 갈라진다 |
| `-n` / `--name` | 세션에 표시 이름을 붙인다 — 나중에 `--resume`으로 찾기 쉬워진다 |

`-c`와 `-r`의 차이가 실수 지점이다. `-c`는 **고르지 않는다** — 가장 최근 것을 집는다.
여러 세션을 번갈아 쓰고 있었다면 이어붙일 대상이 내 생각과 다를 수 있다.

**비용·모델 축**

| 플래그 | 무엇이 달라지나 |
| --- | --- |
| `--model <이름>` | 모델 선택 |
| `--effort <수준>` | 노력 수준 |
| `--max-budget-usd <금액>` | API 지출 한도 — **비용 축에 직접 걸리는** 플래그 |
| `--max-turns <수>` | 에이전트 턴 제한 |
| `--output-format` | 비대화식 출력 형식(`text` / `json` / `stream-json`) |

**권한·진단**

| 플래그 · 명령 | 무엇이 달라지나 |
| --- | --- |
| `--permission-mode <모드>` | 권한 모드 지정(`default`·`acceptEdits`·`plan`·`auto`·`dontAsk` 등) |
| `--add-dir <경로>` | 작업 디렉터리 추가 |
| `--setting-sources` | 설정을 어디서 읽을지 고른다(`user`·`project`·`local`) |
| `--debug` / `--debug-file <경로>` | 디버그 로그 — **설정이 실제로 먹었는지 볼 창구** |
| `claude doctor` | 셋업 진단 |
| `claude --version` | 버전 — 이 노트를 읽기 전에 먼저 볼 값 |

⚠️ 권한 프롬프트를 **통째로 건너뛰는 모드**도 존재한다(플래그 이름에 `dangerously`가
들어 있다). 이름에 붙은 경고는 과장이 아니라 설명이므로 **이 노트는 사용법을 적지 않는다.**
권한을 좁히는 수단은 문서로 남길 가치가 있지만, 넓히는 수단은 복사되기 쉽다.

## 대화 중 — 세션 조작 표면

**컨텍스트·비용** — 이 노트의 주제에 가장 직접 닿는 것들이다.

| 커맨드 | 무엇을 하나 |
| --- | --- |
| `/context` | 지금 **무엇이 컨텍스트를 먹고 있는지** 그리드로 보여준다 |
| `/usage` (별칭 `/cost`) | 토큰 사용량 |
| `/compact [지시]` | 대화를 **요약해** 컨텍스트를 확보한다 — **세션은 그대로 이어진다** |
| `/clear [이름]` | **빈 컨텍스트로 새 대화**를 시작한다 |
| `/btw <질문>` | 기록에 남기지 않고 곁가지 질문 |

**세션 갈래**

| 커맨드 | 무엇을 하나 |
| --- | --- |
| `/resume` | 이전 대화로 돌아간다 |
| `/branch [이름]` | 다른 방향을 시도할 **분기 대화**를 만든다 |
| `/fork [프롬프트]` | 현재 대화를 **새 백그라운드 세션**으로 복사한다 |
| `/background [프롬프트]` | 이 세션을 백그라운드 에이전트로 분리한다 |
| `/tasks` | 이 세션의 백그라운드 작업 목록 |
| `/subtask` | 곁가지 작업을 서브에이전트에 위임한다 |

**입력 첫 글자가 모드를 바꾼다**

| 접두 | 무엇을 하나 |
| --- | --- |
| `/` | 커맨드·스킬 (메시지 **맨 앞**에서만 인식된다) |
| `!` | 셸 모드 — Claude를 거치지 않고 실행하고 **출력을 컨텍스트에 붙인다** |
| `@` | 파일 경로 멘션(자동완성) |
| `?` (빈 입력) | 단축키 도움말 토글 |

**자주 쓰는 단축키**

| 키 | 무엇을 하나 |
| --- | --- |
| `Esc` | 현재 응답·도구 호출을 중단한다(**진행 상황은 남는다**) |
| `Esc` `Esc` | 입력이 있으면 지우고, **비어 있으면 되감기 메뉴**를 연다 |
| `Shift+Tab` | 권한 모드 순환 |
| `Ctrl+O` | 트랜스크립트 뷰어 — 도구 호출·실행 정보를 펼친다 |
| `Ctrl+B` | 실행 중인 작업을 백그라운드로 보낸다 |
| `Ctrl+R` | 명령 히스토리 역방향 검색 |
| `Ctrl+G` (또는 `Ctrl+X` `Ctrl+E`) | 기본 편집기에서 프롬프트를 작성한다 |
| `Ctrl+J` | 줄바꿈 — **설정 없이 모든 터미널에서** 된다 |
| `Ctrl+T` | 작업 목록 토글 |
| `Ctrl+C` | 작업 중단 / 입력 지우기 |

`Ctrl+J`를 따로 적은 이유가 있다. 줄바꿈 방법은 여러 개인데 **대부분 터미널 설정에
의존**한다. `Shift+Enter`나 `Option+Enter`가 안 먹는 환경에서 "줄바꿈이 안 되는
클라이언트"라고 결론 내리기 쉽지만, 실제로는 **경로가 하나 더 있다.**

표에서 헷갈리는 한 쌍만 짚어 두면 — **`/compact`는 같은 세션을 이어가며 압축하고,
`/clear`는 컨텍스트를 비운 채로 다시 시작한다.** 이름이 비슷해 바꿔 쓰기 쉬운데
비용에서는 갈린다. 왜 갈리는지는 바로 아래 ①에서 다룬다.

## 그럴듯해서 속은 것 ① — 「길어졌으니 정리하자」는 이미 늦다

세션의 컨텍스트는 **줄지 않고 누적만 한다.** 대화가 길어지면 요청 1건이 실어 보내는
컨텍스트가 함께 커지므로, **같은 일을 하는 같은 요청 1건이 뒤로 갈수록 몇 배 비싸진다.**

이게 왜 안 보이냐면, 토큰 축이 하나가 아니기 때문이다.
세션 트랜스크립트의 `message.usage`에는 **단가가 서로 다른 네 축**이 따로 기록된다.

| 축 | 무엇인가 |
| --- | --- |
| `input_tokens` | 캐시가 적용되지 않은 입력 |
| `output_tokens` | 생성된 출력 |
| `cache_creation_input_tokens` | 캐시 쓰기 |
| `cache_read_input_tokens` | 캐시 읽기 — **누적된 컨텍스트를 매 요청 다시 태우는 값** |

넷을 합쳐 "토큰 몇 개"로 세면 비용을 못 읽는다. 한 저장소의 세션 트랜스크립트를 집계한
기록에 따르면 **전체 토큰의 약 97%가 캐시 읽기**였다(2026-08-21 실측, 저장소 1개 기준).
즉 체감상 "출력이 길어서 비싸다"고 생각했던 것이 실제로는 **입력 재전송**이었다.

⚠️ 이 「97%」는 **토큰 수 기준**이다. 같은 데이터에서 **비용 기준 비중은 다른 값**이 나온다
— 네 축의 단가가 서로 다르기 때문이다. 두 값은 이름이 거의 같아서(「캐시 읽기 비중」)
**축을 안 적으면 섞인다.** 그리고 섞인 채로도 두 값 다 그럴듯해서 검산을 통과한다.

⇒ 배운 것: **컨텍스트를 줄이는 수단과 세션을 끝내는 수단은 다르다.**
요약은 컨텍스트를 압축하지만 그 요약 자체가 요청 1건이고, 압축한 뒤에도 **같은 세션을
계속 이고 간다.** 그래서 규칙은 "길어지면 정리한다"가 아니라 **"미션이 끝나면 세션도
끝낸다"** 가 된다. 작업 단위로 끊는 것이 단일 최대 절감 레버다.

## 그럴듯해서 속은 것 ② — 서브에이전트 비용이 `0`으로 보인다

비용을 세어 보려고 트랜스크립트를 직접 집계했다.
Claude Code는 세션마다 `~/.claude/projects/<슬러그>/`에 JSONL을 남긴다.
최상위 `*.jsonl`만 모아 셌더니 서브에이전트 요청이 **0건**으로 나왔다.

0건을 보고 "이 저장소는 서브에이전트를 거의 안 쓰니 비용도 없다"고 읽었다. 틀렸다.
하위 로그는 **세션 UUID 디렉터리 안에 따로** 있었다.

```text
최상위만 수집   서브에이전트 요청 0건    → "서브에이전트 비용 없음"
재귀 수집       메인 48 / 서브 109      → 서브가 메인의 두 배가 넘는다
```

(2026-08-21 실측, 저장소 1개 기준)

⇒ 배운 것: **`0`은 「없다」가 아니라 「못 봤다」일 수 있다.**
두 결과는 화면에서 **같은 모양**이다. 부정 결과(없음·0건·통과)는 **관측 경로가 살아
있었음을 함께 보여야** 유효하다. 재귀 탐색은 특히 위험하다 — 깨진 것은 하나도 없고
**내가 본 범위가 한 단계 좁았을 뿐**인데, 그것을 알려주는 신호가 아무것도 없다.

계측 단위도 같은 자리에서 어긋났다. **"요청 수"는 고유 `requestId` 수**이지 줄 수가
아니다. 같은 응답이 트랜스크립트에 여러 줄로 반복 기록되므로 줄을 세면 값이 부풀려진다.
**값이 틀린 것보다 단위가 어긋난 정답이 위험하다** — 오답은 언젠가 걸리지만 그것은
검산을 통과하며 남는다.

## 그럴듯해서 속은 것 ③ — 경과 시간은 벽시계다

서브에이전트 실행 메타에 붙는 소요 시간은 **벽시계 시간**이다.
그 사이 노드가 멈춰 있었다면 **정지 구간이 통째로 포함된다.**
그 값을 성능 기준선으로 박제하면 다음 사람이 정상 속도를 보고 "느려졌다"고 오진한다.

반대 방향의 함정도 있다. **블로킹 호출은 체감 경과가 `0`이다.**
도구 호출이 한 시간 걸려도 대화 흐름에서는 결과 한 덩이로 돌아오기 때문에,
그 시간이 어디로 갔는지 흐름만 보고는 알 수 없다.
실제로 **내 작업에 걸린 시간을 다른 세션 탓으로 오인**한 적이 있다.

⇒ 배운 것: 오래 걸릴 호출은 **앞뒤로 시각을 찍는다.**
시간 수치도 다른 수치와 똑같이 **「무엇을 세는가」** 를 함께 적어야 귀속이 된다.

## 확인 방법

표를 읽는 것으로는 부족하다. 자기 환경에서 이 순서로 확인한다.

```text
① 버전·환경   claude --version  ·  claude doctor
              ← 이 노트의 표가 자기 버전에 맞는지 먼저 본다
② 컨텍스트    /context
              ← 무엇이 컨텍스트를 먹고 있는가. 예상과 다른 항목이 있으면 그게 답이다
③ 사용량      /usage
              ← 네 축이 따로 보인다. 캐시 읽기가 지배적인지 확인한다
④ 계측 경로   ~/.claude/projects/<슬러그>/ 를 재귀로 세고, 최상위만 센 값과 대조한다
              ← 둘이 같으면 하위(서브에이전트) 로그를 못 보고 있는 것이다
```

④가 이 노트에서 제일 중요한 확인이다. **두 값이 같다는 것 자체가 증상**인데,
한쪽만 보면 그냥 "서브에이전트를 안 썼구나"로 읽힌다.

그리고 ②·③에는 **음성 대조**를 붙여야 값이 의미를 갖는다.

```text
⑤ 음성 대조   같은 질문을 긴 세션과 /clear 직후의 새 세션에서 각각 던지고 ③을 비교한다
              두 값이 같게 나오면 측정하고 있는 것이 컨텍스트 크기가 아니다
```

## 그래서 무엇을 배웠나

띄우는 법은 플래그 몇 개로 끝나지만, **끊는 법은 규율이다.**
CLI가 제공하는 것은 수단이고, 비용을 결정하는 것은 **세션을 어디서 자를지에 대한 판단**이다.
그 판단을 하려면 먼저 **보여야** 하는데, 기본 화면은 그것을 보여주지 않는다.

이 노트의 표는 **저절로 낡는다.** 그래서 헤더에 버전과 확인 시점을 박아 두었다.
낡은 레퍼런스가 위험한 이유는 틀렸다는 사실을 **알려주지 않기** 때문이다 —
값이 틀린 문서보다 **언제 기준인지 안 적힌 문서**가 위험하다.
축은 다르지만 형태는 이 위키의 다른 노트들과 같다.
[엔진마다 값이 갈리는 SQL](cross-engine-sql.md)에서는 같은 SQL이 엔진에 따라 다른 값을
냈고, [Dagster 파티션](dagster-partitions.md)에서는 날짜 문자열의 뜻이 네 군데서 갈렸다.
이 노트까지 셋 다 **성공 신호가 뜬 채로 틀린다.**
